# KAN-472 — run record, 2026-09-28

Finished the failed PT refresh by hand and filled `overture_poi.country_code`.
One script, `cloudflare/extraction/repair_pt_refresh.py`, dry-run by default.
No migration, no Worker deploy, no container build: this changes data only.

## Why the run was needed

The 2026-09-25 refresh (run `7ac6dab3-…`) died mid-load on
`ConnectionError: HTTPConnectionPool(host='d1.internal', port=80): Read timed
out.` It was started to pick up KAN-460's name columns and could never have
done so — Overture's `names.common` is empty for every place in the theme
(see KAN-471 for the measurement). It re-extracted the same release
(`2026-08-19.0`) and the same 350,415 rows, so the refresh diff was empty:
0 new, 0 changed, 0 retired. **The retire pass was therefore deliberately not
run** — retiring here would mark rows the release still carries.

What it left behind, and what this run fixed:

| | before | after |
|---|---|---|
| candidates on the previous archive key | 143,613 | 0 |
| candidates without `country_code` | 143,613 | 0 |
| served rows without `country_code` | 215,994 | 0 |
| import row | `failed`, counters zeroed | `mapped`, counters measured |

## What was written

35 statements, one request each, bounded by leading-character bucket of
`overture_id` so no statement attempted 216k row-writes. 359,643 rows.

1. **1–17, the key move.** The 143,613 candidates still on
   `…/1ea48e22-….csv` moved to `…/7ac6dab3-….csv`, with `last_seen_source_key`
   and the import's country code. Guarded on the old key. `promotion_status`
   and `promotion_note` are not in the SET — the decisions were never touched
   by the failed run and are not touched here.
2. **18, the import row.** `status='mapped'`, `previous_source_r2_key=NULL`,
   `last_error=NULL`, counters set to the measured truth
   (350,415 staged / 215,994 promoted / 44,110 rejected / 90,311 pending,
   `new/changed/retired = 0`). `raw_extract_r2_key` was **kept** — KAN-471
   reads that archive. Statement pinned to this run id and archive key.
3. **19–35, `country_code`.** 215,994 served rows, each value read from its
   own `overture_candidate` row rather than a literal, guarded on
   `country_code IS NULL`. Only that column was written.

Buckets 17 and 35 (everything outside hex) each matched one row, which is why
they exist: two ids do not start with a hex character and would otherwise have
been skipped silently.

## What was deliberately not written

`name`, `name_local`, `name_en`, `name_local_lang`, `names_json`,
coordinates, category, types, attributes, brands, decisions. The name columns
stay NULL — that is the correct state for "no recorded translation", it is
KAN-471's destination, and a NULL `name_languages_json` is what keeps the
Settings picker disabled until then. Curated and Multibanco country codes are
out of scope.

### No display change, by design

`selectPoiName` previously took the no-country branch and returned `name`.
With a country it resolves the preference, defaults to `'native'`, and returns
`nonBlank(name_local) || name` — and `name_local` is NULL, so it returns
`name`. Identical string for every row. The Settings picker stays disabled
because it needs `languages.length > 1` from `name_languages_json`, which is
untouched. The only wire difference is `country_code` being present, which the
offline cache now stores.

## Re-running

The script is idempotent: every statement is guarded on `IS NULL` or on the
old key, and the import row update is pinned to the run id and archive key. A
second run writes nothing, which is covered by a test.
